# الإصدار ٢٨ — أخبار فعلية ودخول موحّد وصلاحيات

## الأخبار والشكل

استُبدلت أخبار أرقام إصدارات GitHub بعناوين أخبار تقنية فعلية من قنوات RSS الرسمية لسكاي نيوز عربية وBBC Technology وArs Technica، تُجمع على خادم التطبيق عبر /api/tech-news. تُرشّح الخلاصة العربية لاستبعاد العناوين الصحية وغير التقنية، وتُرفض الروابط خارج نطاق الناشر والأخبار القديمة جدًا. قد تختلف لغة العنوان حسب المصدر؛ لا توجد ترجمة مختلقة. أرقام الإصدارات القديمة لا تُستخدم مجددًا.

بطاقة زجاجية هادئة مرتفعة عن أسفل الشاشة؛ خبر واحد في كل مرة بانتقال لطيف من اليمين وتلاشٍ، بدل النص المتحرك باستمرار. أزيلت شارة «الأخبار» وكلمة «المصدر» المنفصلة. اسم الناشر نفسه رابط تحت عنوانه، بجانبه تاريخ النشر. يُوقف المرور على البطاقة المؤقت، وتُحترم إعدادات تقليل الحركة. المدة الافتراضية ٢٠ ثانية مع إطالتها للنصوص الطويلة. لا تُجلب المصادر إلا كل ٣٠ دقيقة؛ توجد ذاكرة محفوظة للعمل دون الإنترنت.

يمكن إضافة الاقتباسات التقنية الموثقة الموجودة في المكتبة إلى التدوير من /news. يظهر اقتباس واحد بعد ثماني بطاقات أخبار على الأقل (أو يبقى اقتباس ثابت إذا لم توجد أخبار). هذه الاقتباسات من المكتبة السابقة بمصادرها وليست نصوصًا منسوبة عشوائيًا.

## الدخول المحلي — Mac وWindows

الإدارة والأخبار تستخدمان /login نفسه، ولا يوجد رمز PIN منفصل للأخبار. اختفت المصادقة التجريبية التلقائية. عند تشغيل النسخة لأول مرة إذا لم يوجد data/staff.json، يظهر FIRST SETUP CODE في نافذة الخادم. افتح /login وأدخل الرمز واختر كلمة مرور محلية لحساب المسؤول الرئيسي 3looolyyy@gmail.com. هذا لا يغيّر حساب Supabase أو كلمة مروره الحالية. لم تُضمّن أي كلمة مرور جاهزة أو تخمين لكلمة المرور الجزئية التي ذُكرت في المحادثة.

إذا كان مجلد data يحتوي حسابات من هذه النسخة أو أحدث، تبقى الحسابات وكلمات مرورها كما هي ولا يعاد الإعداد. لا تحذف staff.json عند التحديث. كلمات المرور المحلية محفوظة كاشتقاق scrypt مع salt، والجلسات ملفات ارتباط HttpOnly/SameSite وتبقى حتى ١٢ ساعة. إعادة تشغيل الخادم تتطلب تسجيل دخول المحررين من جديد؛ روابط التلفزيون لا تتطلب تسجيل دخول.

من «الحسابات والصلاحيات» أو /users ينشئ المسؤول الكامل أسماء مستخدمين وكلمات مرور ويحدد: مسؤول كامل، أخبار، محتوى يومي، أو الجمع بين الأخبار والمحتوى اليومي. لا يحتاج المعلم بريدًا إلكترونيًا. صلاحيات الخادم ترفض العمليات غير المصرحة حتى لو استُخدمت واجهة API مباشرة. محرر المحتوى يعدل النص والصور والمواضيع والجدولة؛ لا يغيّر القالب أو يدير الحسابات. محرر الأخبار ينشر عبر /news فقط. لا يمكن تعطيل المسؤول الرئيسي أو نزع صلاحياته. يمكن تعطيل الحسابات الأخرى أو إعادة تعيين كلمات مرورها.

بيانات الحسابات تخص هذا الجهاز ومجلد data؛ ليست مزامنة حسابات بين خوادم محلية مختلفة. أذونات التحرير لا تغيّر نظام روابط العرض المتعددة والشاشات المتصلة بالحاسوب.

## السحابة وNetlify — إعداد إضافي مطلوب قبل الرفع

لم يُرفع شيء إلى GitHub ولم يتم نشر أو تعديل مشروع Supabase الحقيقي. لتشغيل صلاحيات السحابة طبّق migrations/0006_staff_permissions.sql بعد 0005. تم اختبار SQL في PostgreSQL مع مخطط Auth/Storage اختباري، وليس على مشروعك الحقيقي.

تظل كلمة مرور حساب Supabase الحالي 3looolyyy@gmail.com دون تغيير؛ يمنحه الترحيل صلاحية المسؤول الكامل. يحتفظ باقي المستخدمين الموجودين بكلمات مرورهم لكن يمنحهم المسؤول أذونات من /users. قبل ترحيل مشروع جديد أنشئ حساب المسؤول الرئيسي بهذا البريد في Supabase إن لم يكن موجودًا. أبقِ التسجيل الذاتي مغلقًا.

تحتاج وظائف Netlify إلى SUPABASE_SERVICE_ROLE_KEY على الخادم فقط، إضافة إلى SUPABASE_URL وSUPABASE_ANON_KEY أو متغيرات VITE_SUPABASE_URL وVITE_SUPABASE_ANON_KEY المتاحة أيضًا لوظائف الخادم. لا تضع مفتاح الخدمة في أي متغير يبدأ VITE_ ولا في ملفات الويب. ملفات الوظائف في netlify/functions وnetlify/lib. يحفظ /users أسماء المستخدمين وحقوقهم في staff_profiles، وينشئ حسابات Supabase خلفية بعناوين داخلية دون الحاجة لبريد المعلم أو إرسال رسائل. الدخول بالبريد القديم متاح، والدخول بأسماء المستخدمين يحتاج الوظائف المضبوطة. صلاحيات RLS تحمي الأخبار والمحتوى والقوالب والتخزين.

## الترقية

فك الضغط كاملًا، وانقل مجلد data القديم إلى المجلد الجديد قبل بدء الخادم. شغّل Start-Mac.command أو Start-Windows.bat. تحتاج Node.js 22 أو 24 على الحاسوب فقط، والهاتف على نفس الشبكة. إذا طُلب إعداد المسؤول بعد الترقية من v27 فهذا متوقع؛ v27 المحلي كان يستخدم رمز أخبار فقط ولم يتضمن حسابات مستخدمين. تظهر جميع الصور والمحتوى والقوالب المحفوظة كما كانت.
