# الإصدار ١٦ — النشر والشاشات المتعددة

- زر «نشر على الشاشة» في الرئيسية يحفظ المحتوى ووضع العرض والقالب معًا. لا تحتاج إلى حفظ خلفية الحصص مرة ثانية. زر «تطبيق وضع العرض» يبقى متاحًا لتغيير الوضع دون نشر نص جديد.
- الشعارات في موضع ثابت سواء ظهرت لوحة التميز أو اختفت. النسب الأصلية للصور محفوظة، ولا تُصغَّر الشعارات تلقائيًا عند إظهار اللوحة.
- في «خلفية الحصص»: منزلق حجم الواجهة ٧٥–١١٠٪ يغيّر الساعة والشعارات واللوحة والنصوص معًا. الخطوط والجزيئات تبقى ممتدة على الخلفية البيضاء.
- للتميز ٣ تبويبات: القائمة الحالية، طالب واحد بتصميم بارز، ومجموعة ببطاقات لطالبين أو ثلاثة أو أربعة. نفس قائمة الطلاب والصور محفوظة عند تغيير النمط. تبقى إمكانية الإخفاء والإضافة والحذف والحجم.
- من «الشاشات»، أضف شاشة واختر «رابط العرض». لكل شاشة رابط خاص مثل /display أو /display2، مع رمز عرض دائم خاص بها في الرابط. افتحه مباشرة على التلفزيون المطلوب؛ لا يطلب تسجيل دخول.
- الرابط يمنح عرض الشاشة فقط. لا تعدّل الرمز في الرابط؛ يمكنك إلغاؤه من الأجهزة المرتبطة في «إعداد الشاشة». بعد حذف شاشة أو إلغاء رابطها، أنشئ رابطًا جديدًا للشاشة المطلوبة.
- ذاكرة العمل دون اتصال ومفاتيح ربط المتصفح منفصلة لكل رابط؛ لا تختلط شاشة بأخرى عند فتح أكثر من شاشة على نفس الكمبيوتر.
- زر Start-Mac.command يشغّل الخادم على الشبكة المحلية ويفتح ويطبع عنوان IP رقميًا مثل http://192.168.1.20:8080/admin. انسخ العنوان المطبوع إلى Safari في الهاتف المتصل بالشبكة نفسها. لا تستخدم IP المثال. اترك نافذة الخادم مفتوحة واسمح باتصالات Node إذا طلب macOS ذلك. إذا تعددت الشبكات، تظهر عناوينها أيضًا، ويمكن تشغيل LAN_IP بعنوان جهازك لاختياره يدويًا.
- إذا لم يكن للجهاز عنوان شبكة، سيستخدم 127.0.0.1 للاختبار على الكمبيوتر فقط ويخبرك بذلك. ليس هذا عنوان الهاتف.

## GitHub / Netlify

- مصدر واحد للنسختين: `npm run build` ينتج `dist` للسحابة، و`npm run build:local` ينتج حزمة الاختبار المحلية `dist-local` ببيانات مستقلة.
- مسارات /display و/display2 وما بعدها يدعمها توجيه React وإعداد Netlify الحالي. لا حاجة إلى استضافة منفصلة لكل تلفزيون.
- روابط العرض تستخدم آلية الرموز والربط الموجودة في Supabase وصلاحياتها الحالية؛ لا تحتاج إلى ترحيل جديد لهذا الإصدار. يبقى `0003_media_video.sql` مطلوبًا لدعم الفيديو من تحديث v15.
- لا تُرفع مجلدات node_modules أو dist-local/data أو مفاتيح البيئة. لا تستخدم الخادم التجريبي المحلي كخادم سحابي عام.
- `npm run test:loop` لاختبارات الحصص واللوحة. بعد `npm run build:local`، استخدم `npm run test:local` لاختبارات الواجهة والنشر وشاشتين مستقلتين. يحتاج Playwright Chromium؛ يمكنك تحديد PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH إذا استخدمت متصفحًا مثبتًا.

هذه حزمة مصدر جاهزة للرفع وتجربة Mac، وليست تأكيدًا على نشرها إلى GitHub أو نجاح Netlify في الحساب الحقيقي.

## التحقق من الحزمة

نجح بناء السحابة والبناء المحلي وفحص TypeScript وlint. نجحت اختبارات الحصص واللوحة الستة. فحص المتصفح على نسخة مؤقتة ببيانات تجريبية تحقق من: النشر من الرئيسية دون حفظ إضافي، الأنماط الثلاثة ومجموعة أربعة طلاب، حجم ١٠٥٪، ثبات الشعارات عند إخفاء اللوحة، عرض الهاتف 390×844 بلا تمرير أفقي، رابطَي /display و/display2 بمحتوى مستقل وتحديث حي، واستقلال نسخ التخزين دون اتصال. لم تظهر أخطاء JavaScript أو طلبات إلى Supabase أثناء الاختبار المحلي. لم يُختبر نشر Netlify في الحساب الحقيقي أو Safari على جهاز iPhone فعلي.
